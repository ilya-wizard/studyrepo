# Signal Scan Protocol

## Mission
Find concrete, recurring problems before inventing solutions. Search broadly across B2B and B2C.

## Strong signal types
- repeated complaints from independent users
- people paying for clumsy/manual workarounds
- spreadsheets, assistants, agencies, scripts, or multi-tool workflows used to patch a problem
- requests for alternatives to an existing product
- churn/cancellation caused by a known missing capability
- regulatory, platform, demographic, or technical changes creating new mandatory work
- niche communities repeatedly asking the same operational question
- products with high demand but obvious experience/pricing/support failures

## Sources
Prefer primary discussion sources: Reddit, specialist forums, app reviews, GitHub issues/discussions, product communities, public Slack/Discord archives when indexed, professional communities, complaint boards, job posts, implementation discussions, and search results revealing workaround behavior.

## Search behavior
Do not search only for "business ideas". Search for language people use when frustrated:
- "I wish there was"
- "is there any way to"
- "alternative to"
- "why is this so hard"
- "we still use spreadsheets"
- "manual process"
- "takes hours"
- "too expensive"
- "any tool that"
- "how do you manage"
- "hate using"
- "cancelled because"

Also search around recent rule/platform/API/pricing changes that force users to change behavior.

## Evidence standard
Before promoting a theme, collect multiple independent signals. For each signal capture:
- date
- source
- URL
- target user
- exact problem
- workaround/current spend
- intensity/frequency clues
- short quote or faithful summary

## Immediate rejection
Reject or heavily penalize:
- generic AI wrappers
- saturated ideas without a narrow wedge
- one viral post with no corroboration
- "nice to have" novelty
- ideas whose buyer/user cannot be named precisely
- opportunities that require large paid acquisition just to test demand
- solutions looking for a problem

## Output
A candidate is a problem statement, not a product pitch. Include: problem, target user, job-to-be-done, evidence, alternatives/workarounds, why existing options fail, why now, plausible monetization, acquisition path, and risks.
