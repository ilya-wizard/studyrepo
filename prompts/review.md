# Cycle review — v2.0

Read latest source-of-truth records and the last cycle's run logs before searching.

First audit integrity: criteria versions, stale generated views, missing citations, feedback provenance, evidence independence, experiment status, spend and commitments. Repair reversible data/format drift, preserve history, and flag access failures. Never fabricate missing values to pass checks.

Review up to three opportunities against actual user reactions and changed primary evidence. Spend review effort on contradictions and experiment outcomes rather than re-ranking the same websites. Separate problem quality, solution quality, user interest and commercial evidence. Reopen a solution only with its trigger or a clearly different solution scope.

For the two current audiences, report new independent evidence, options the user found interesting, field contacts actually made, interviews actually completed, meaningful repeat use, paid commitments and spend. Denominators and periods are required; 'not measured' is valid. Judge progress by decisions and learning, not report volume.

If no experiment is active, prepare the best ready-to-test option and at most two alternatives. Ask once for a focused user choice/interest rating if needed; do not repeat the same unanswered request every run. Do useful preparation meanwhile. Never invent a selection. If one is active, identify the next blocker and keep discovery bounded. A prepared kit is not evidence of execution.

End the cycle with continue/change/test/watch/reject decisions. Retain the same audiences when evidence suggests useful unanswered questions; rotate one audience or query family after two stalled focused passes. Keep 80/20 focus/adjacent discovery and one active experiment. Update config/cycle.json with next dates and focus; preserve fixed recurring scheduling unless the user changes it.

Write a concise weekly review artifact with metrics, evidence changes, decisions and next action. A chat notification is warranted for new evidence, a real decision, an experiment milestone or a new actionable blocker. Do not send repeated 'nothing found' or unchanged requests. Track notified event keys in runs.jsonl. Persist meaningful work, validate and regenerate views in the same commit. On GitHub conflicts re-read/reapply, never force-update.
